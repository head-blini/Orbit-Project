# Claude Code — Orbit development entrypoint

Read and follow `AGENTS.md` first. Before planning or editing, read:
1. `docs/ORBIT-VISION.md` — immutable product identity unless the user explicitly approves a new version.
2. `docs/ORBIT-SCOPE-2026-10-27.md` — approved feature scope.
3. `docs/ORBIT-IMPLEMENTATION-PLAN-2026-10-27.md` — implementation sequencing.

Do not reinterpret Orbit as a coding-only tool, a model switcher, or an AI log viewer. New ideas are proposals, not automatic scope changes. Preserve the general-purpose natural-language workflow, project direction, progress visibility, provider extensibility, and security boundaries.

When collaborating with Codex, use separate branches/worktrees for overlapping work; document handoffs, decisions, file ownership, tests, and remaining issues. Prefer existing official tools and integrations. Do not alter or overwrite existing user changes or secrets. If documents conflict, use the approved vision for product identity, the approved scope for requirements, and the stronger applicable safety/approval constraint.
