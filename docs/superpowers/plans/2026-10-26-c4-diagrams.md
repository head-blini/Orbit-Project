## Decisions and limits

- Alternatives considered: embedding a Mermaid/Structurizr runtime adds execution/dependency surface; overloading the old architecture graph loses boundaries and C4 scope semantics. Choose an explicit, bounded C4 model and existing primitive renderer.
- Source: `{format:'c4-v1',title,view:'context'|'container'|'component',scope,elements,relationships}`.
- Element: `{id,kind:'person'|'system'|'container'|'component',name,description,parentId:string|null,technology:string|null}`. People/systems have null parent and technology. Containers require a system parent and technology; components require a container parent and technology. All parents must be included.
- Relationship: `{id,from,to,description,technology:string|null}`. IDs are unique; endpoints must be visible leaves. Technology is required between two container leaves. Self relationships are explicitly unsupported. Multiple directional relationships and cycles are allowed; exact duplicate relationships are rejected.
- Context scope is a system: only people/systems. Container scope is a system boundary: its direct containers plus external people/systems. Component scope is a container and its parent system boundary: its direct components, sibling containers in that system, external people/systems. Require at least one primary container/component; disconnected drafts and empty relationship lists are valid.
- 12 elements including boundaries, 24 relationships, 256 KiB UTF-8 source, ASCII IDs at most64characters; title/name/technology80Unicode codepoints, description160. Exact fields, dense arrays, valid XML text, no HTML/URLs/directives or hidden controls. The source is authored architecture, not source-code verification.
- A complete view remains on one overview canvas; text wraps by grapheme without truncation. Scope/title/type/technology/descriptions and legend remain visible. Max3600×1200points and existing primitive budgets; layout failure is explicit `C4_LAYOUT_LIMIT` before persistence. No partial model or disconnected pagination.
- Generic canvas contract is identical to existing sequence primitives. Extract types/limits into `shared/canvas.ts`; preserve sequence aliases and `sequence-v1` bytes/behavior. No arbitrary shapes, style strings, links, media or external relationships.
- Deployment/landscape/dynamic/code diagrams, other UML and PDF remain separately incomplete. No inferred architecture from file graphs or forged freshness metadata.
