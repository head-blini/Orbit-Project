# Orbit UI E2E implementation plan

**Goal:** `node scripts/verify-orbit-ui.mjs` runs existing quality gates and real local Chrome UI scenarios using installed agent-browser, without user data or AI calls.
**Scope:** Test harness and documentation only. User explicitly delegates implementation and forbids browser execution in the Codex sandbox.

- [x] Add failing unit tests for fail-closed CLI responses, path containment, isolated environment, process timeout, report status.
- [x] Implement reusable harness helpers and a test-only server entry using production Store/Controller/Projects/createHttpServer. Inject an AI factory that always rejects. Bind loopback on an allocated port, support IPC shutdown/restart, preserve the same fixture DB.
- [x] Implement all 12 navigation assertions, UI project creation/selection, planning approval/Task, Artifact round trip, synthetic privacy block, reload/restart persistence, both viewport captures, JS/console error collection, finally cleanup.
- [x] Execute only `--check-only`, static syntax checks, typecheck, unit/full tests in sandbox. Record `not_run` for all browser scenarios. Normal PowerShell owns real browser execution.
- [x] Document commands, evidence, exit codes, limitations and failure-specific minimal remedies in docs/ORBIT-E2E-RESULTS.md. Runs keep JSON/Markdown/CLI/server logs and screenshots in .local/ui-e2e/<unique-run>/.

Constraints: no new framework/install, no arbitrary user URLs/project paths, no shared Chrome session or profile, no auth files, no external AI factory, no production API/schema/Runner changes. Owned processes only; never kill by executable name. Failures and incomplete cleanup must cause nonzero exit. Browser-dependent steps cannot pass in check-only mode.

E2E status is deliberately `not_run`, screenshots 0. A read-only reviewer checked selectors/isolation/restart and identified abort-cleanup and initial navigation evidence gaps; both corrected.
