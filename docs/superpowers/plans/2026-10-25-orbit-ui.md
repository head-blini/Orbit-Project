# Orbit UI implementation plan

> Execute inline with executing-plans and test-driven-development. Main agent owns UI edits; a read-only reviewer checks regressions.

**Goal:** Preserve current functionality and security while giving Orbit twelve independent Korean-first pages.
**Architecture:** React shell with hash navigation and a shared persisted project ID. Existing server snapshot, SSE, CSRF POST, editors and Codex actions remain authoritative. Lazily visited editors stay mounted but hidden across navigation; project changes isolate editor state. A single Agent Center component also serves the optional command drawer.
**Tech stack:** Existing React 19 / TypeScript / CSS; no new dependencies.
**Spec:** User's Orbit UI request, root AGENTS.md and docs/00–03, 06–07. This is UI reorganization, not a phase gate advancement.

## Constraints and decisions
- Preserve dirty worktree, backend, SQLite/WAL/SHM, credentials, execution history and existing settings.
- Main navigation: Dashboard, Projects, Planning Studio, Agent Center, Development, Visualization Studio, Automation. Bottom: Model Providers, Extensions, Privacy & Security, Usage & Analytics, Settings.
- Korean labels with consistent English page subtitles. 240px sidebar; responsive collapsed navigation; compact project/status/settings header.
- Dashboard uses only actual snapshot and saved task data. Unsupported automation/extensions/usage/general settings show 준비 중.
- Project context and execution workspace must match before connect/send; selecting a planning-only project must never execute in a previous project's workspace.
- Navigation persists through URL hash; project preference uses a new namespaced localStorage key, with storage failures tolerated. No draft content in localStorage.
- User opted out of design approvals. No commits of pre-existing changes or installations.

## Review focus
1. Switching projects during requests cannot leak stale records or execute in a different workspace.
2. Navigation and browser refresh retain selected page/project; invalid routes and missing projects recover safely.
3. Offline/pending/active execution guards and server authority remain intact.
4. Editors retain unsaved text across navigation; hidden pages must not create requests until first visited.
5. Narrow screens, keyboard navigation, drawer focus and long paths remain usable.
