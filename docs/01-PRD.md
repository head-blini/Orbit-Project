# PRD — AI Coding Control Center v0.3

## 1. 제품 정의
**사용자:** ChatGPT/Claude/Gemini 등의 구독 여부와 관계없이, 최소 한 개의 지원 코딩 에이전트로 개발하고 싶은 개인·소규모 팀. 사용자는 ChatGPT가 없어도 된다.
**문제:** AI 웹 기획과 CLI 실행이 서로 단절되고 세션·변경·검증·사용량이 흩어짐. 여러 AI를 강제하면 별도 구독 비용과 설치 부담이 커짐.
**가치:** **AI 제공자를 자유롭게 선택**하여 기획·개발·검토·검증을 하나의 로컬 웹에서 관리하고, 단일 에이전트부터 다중 에이전트까지 단계적으로 확장한다.

## 기본 사용자 여정 (제품의 중심)
**기획 입력 방식 선택(내장 편집/연결 AI/외부 도구) → 버전 검토·승인 → Task 생성 → 사용 가능한 코딩 에이전트 실행 → 테스트·검토(선택적 교차 리뷰) → 승인·결과 기록 → 선택한 기획 도구로 피드백.**

- **ChatGPT 이용자 경로:** ChatGPT 웹 기획 → 파일/본문 import → Claude Code 또는 Codex로 구현/리뷰.
- **ChatGPT 미이용 경로:** Claude 웹 문서 import 또는 관제센터 내 편집·Claude Code 읽기 전용 기획 → Claude Code 개발·테스트 → 새 검토 세션/사람 검토 → 완료.
- **다른 제공자 경로:** Codex-only / Gemini CLI / OpenCode 등 어댑터가 지원되는 범위에서 동일한 작업 흐름.
- **에이전트 미연결 상태:** 기획 작성·자료 import·기존 Git 프로젝트 정보는 볼 수 있지만 AI 명령 버튼은 비활성화하고 연결 안내를 제공한다.

## 2. 사용 시나리오
### US-00: 제공자 중립 기획 → 승인 → 작업 인계 (P0, V1 필수)
관제센터 내 직접 작성, 지원되는 AI 기획 모드, 외부 ChatGPT/Claude/Gemini 웹에서 생성된 본문/파일 중 하나를 이용해 기획안 작성 → **Ideas & Planning**에서 Markdown/JSON 또는 편집 결과를 미리보기 → 요구사항·완료조건·제약·미결정 사항 확인 → 버전 승인 → Task 초안 생성.
- 검증: 어느 단계에서도 ChatGPT 계정이 필요하지 않음. 승인되지 않은 기획안은 자동 실행 금지. 모든 출처에 동일한 schema/version 규칙 적용.
### US-00B: 구현 이슈를 선택한 기획 경로로 되돌려 재기획 (P0)
실패 테스트·설계 변경 질문을 **제공자 중립 피드백 패키지**로 내보내기 → 내부 편집기/연결 AI/외부 웹에서 수정 → 새 기획 버전과 기존 버전의 diff·영향 Task 확인 → 명시적 승인 뒤 반영.
- 검증: 기존 실행 Task는 승인 전까지 자동 변경되지 않음. 모델 전환 시 내부 모델 상태가 아닌 구조화 문서와 코드 기준점을 인계.
### US-00C: 단일 에이전트 사용자 (P0, V1 필수)
Claude Code 또는 Codex 중 **한 개만** 설치·인증한 사용자도 기획·코드 실행·테스트·사용자 승인까지 완료할 수 있음.
- 검증: UI가 다른 서비스 연결을 강제하지 않음. 교차 리뷰 대기 때문에 완료가 무한히 Blocked 상태가 되지 않음. 동일 에이전트의 새 세션 검토를 선택한 경우 `same_provider_review`로 구분.
### US-00D: 제공자 감지·선택형 온보딩 (P0)
첫 실행에서 설치된 CLI와 사용 가능 기능만 표시하고, ChatGPT/Claude/Gemini 로그인 강제 없이 프로젝트와 기획을 생성. 필요할 때 개별 CLI의 공식 로그인 안내를 제시.
- 검증: 미연결 AI는 `not_configured`, 인증 필요는 `auth_required`, 한도 미확인은 `unknown`으로 표시; 0% 사용과 혼동하지 않음.
### US-01: 단일 AI 기능 구현 (P0)
프로젝트를 선택 → 기능·금지사항·완료 조건을 입력 → AI/모드 선택 → 전용 worktree에서 코드 수정 → 실행 상태·diff 확인 → 테스트 → 승인/보류.
- 검증: 웹 새로고침 후 동일 작업/로그/수정 파일 확인; 승인 전 main 브랜치 변경 금지.
### US-02: 리뷰 — 교차 AI 또는 단일 AI/사람 (P0)
구현한 브랜치의 base/head SHA를 고정 → 가능할 때 다른 AI에게 읽기 전용 리뷰 지시, 없으면 별도 새 검토 세션 또는 사람 검토 → 발견사항에 위치·재현 경로·확인 상태 기록 → 검증된 지적만 수정 큐에 올림.
- 검증: 리뷰 대상의 기준 커밋과 head SHA가 남고, 재실행 도중 변경되면 '검토 기준 변경됨' 표시.
### US-03: 작업 중단과 복구 (P0)
실행 중 사용량 제한/프로세스 오류/서버 종료 → 'Interrupted/Blocked' 상태와 원인 기록 → 수동으로 이어 하기/다른 AI에 인계.
- 검증: 서버 재시작이 동일 프롬프트를 자동으로 다시 실행하지 않음.
### US-04: 사용량·승인 한눈에 보기 (P0)
연결한 제공자별로 **지원되는 지표만** 사용률·리셋 시각과 함께 보여주고, 해당 기능이 없는 제공자는 미지원으로 표시.
- 검증: 수집 불가 상태에서 0%/무제한을 표시하지 않음.
### US-05: 코드 그래프 및 변경 영향 (P1)
커밋 SHA 기준으로 Graphify 인덱스 생성 → 노드/엣지 클릭 → 관련 파일/함수/테스트와 변경 내용 열기.
- 검증: 인덱싱 기준과 현재 HEAD가 다르면 '그래프 오래됨' 표시.
### US-06: 확장 기능의 안전한 관리 (P1)
프로젝트별로 MCP/스킬/플러그인의 설치·활성 여부 조회, 변경 미리보기, 백업 후 적용.
- 검증: 설정을 수정하기 전에 대상 파일·범위·차이점과 위험한 설치 스크립트를 표시.
### US-07: AI 자동 협업 (P2)
규칙에 따라 작업 분해/사용 가능한 담당 AI 추천/병렬 worktree/가능할 때 독립 리뷰/통합 테스트 제안.
- 검증: 반복 및 호출 상한, 파일 충돌/실패 처리, 최종 병합은 사람 승인.

## 4. 필수 기능 FR
- **FR-00A** 제공자에 관계없는 기획안(내장 편집/연결 에이전트/외부 Markdown·JSON·붙여넣기)의 작성·가져오기, 원문 보관, 필드 검증, 미리보기.
- **FR-00B** 기획안 상태 `DRAFT/REVIEW_REQUIRED/APPROVED/SUPERSEDED`, 문서 버전 불변·출처·승인자·승인 시각 기록.
- **FR-00C** 승인된 기획안의 요구사항/완료 조건을 프로젝트 Task 초안으로 변환하고 추적 연결. 미결정 사항은 자동 코딩 금지.
- **FR-00D** 빌드·리뷰·결정 결과를 모든 기획 도구에서 읽을 수 있는 Markdown 패키지로 내보내기; 후속 기획안은 기존 승인 버전과 diff·영향 Task 표시, 승인 후 반영.
- **FR-00E** Planning·Coding·Review 역할별 제공자와 실행 모드를 독립 선택하고, 미구성·미지원 기능을 표시.
- **FR-00F** 최소 하나의 코딩 에이전트만 연결돼도 구현·테스트·사람 승인까지 완료. 타 제공자 검토는 선택이며 리뷰 출처를 정확히 표시.
- **FR-01** 등록된 프로젝트 루트 경로만 접근. Git 저장소 유효성·작업 트리 오염 여부 확인.
- **FR-02** Provider Registry를 통해 현재 지원되는 에이전트의 설치·버전·인증·권한·capability를 동적으로 표시. 미연결 제공자 가입을 강제하지 않음.
- **FR-03** 프로젝트·작업·프롬프트·세션·실행·작업 결과를 별개의 ID로 기록.
- **FR-04** 이벤트 스트림에서 응답·툴 사용·명령 실행·파일 변경·승인 요청의 차이를 시각화.
- **FR-05** 실행 중단·재개·대체 AI 인계. 자동 재실행 시 기본적으로 사용자 승인 필요.
- **FR-06** P0 작업은 가능하면 별도 Git worktree에서 실행; 기존 수정사항 보존.
- **FR-07** 저장된 테스트/빌드 명령은 종료 코드와 stdout/stderr, 실행 SHA와 함께 기록.
- **FR-08** 리뷰는 제공자에 관계없이 읽기 전용 프로필/권한으로 시작하고, base/head SHA를 고정. 교차 AI 리뷰 미지원 시 별도 새 세션/사람 검토 또는 승인된 스킵 정책을 표시.
- **FR-09** 완료 조건에 필요한 테스트가 누락되면 '미검증'으로 남음.
- **FR-10** MCP/스킬 설정 변경은 기본적으로 미리보기 → 사용자 승인 → 백업 → 원자적 적용 → 진단 순서.
- **FR-11** 연결된 제공자만 구독 사용률/세션 토큰/API 비용 추정치를 별도 단위와 출처로 표시. `unknown`, `unsupported`, `auth_required`를 0과 구분.
- **FR-12** 사용자에게 중요한 실행·승인·거절·비정상 종료는 감사 로그로 영구 기록.

## 5. 비기능 요구사항 NFR
- **Local-first:** 초기 기본 서버는 `127.0.0.1` 바인딩, TLS 없는 LAN/공인 네트워크 노출 금지.
- **안전:** 로컬 CLI 인증 정보 원본을 앱 DB·브라우저·로그에 저장하지 않음. CLI는 사용자가 직접 공식 로그인.
- **복원력:** DB 트랜잭션/SQLite WAL, 이벤트 시퀀스 기반 재동기화, 비정상 종료 후 orphan run 탐지.
- **성능:** 원시 로그/그래프 노드를 전부 브라우저로 보내지 않고 페이지·필터·검색으로 제한.
- **이동성:** macOS·Windows(필요 시 WSL2)·Linux를 목표로 하되, 최초 검증 환경만 '지원'으로 표기.
- **투명성:** '계획/실행/테스트/리뷰/병합'을 별도 증거로 표시. 명령 종료 코드 0 하나로 품질 완성을 주장하지 않음.
- **비용:** 사용 가능한 각 공급자의 공식 구독을 우선 활용. 외부 분석 서비스·API 과금·로컬 모델 하드웨어 비용은 출처별로 구분, 명시적 opt-in. **ChatGPT 구매 필수 조건 금지.**
- **사용성:** CLI로 돌아갈 수 있는 링크/명령 제공. 상태·이벤트·Diff는 키보드로 탐색 가능.

## 6. MVP 수용 테스트
1. **ChatGPT 계정 없이 Claude Code 하나만** 연결해 관제센터 내 기획 또는 외부 문서 가져오기 → 승인 → 기능 구현 → 테스트 → 사용자 승인까지 완료한다.
2. **Codex만 연결한 경우**에도 ChatGPT 웹 기획을 필수로 요구하지 않고 같은 과정을 수행한다(해당 사용자의 Codex 인증 방식은 별도).
3. **연결된 에이전트가 전혀 없을 때** 기획 작성·프로젝트 열람은 가능하고 AI 실행은 명확한 설치 안내와 함께 비활성화한다.
4. ChatGPT·Claude 웹·Gemini 등 출처별 예시 Markdown/JSON이 동일한 검증/버전·승인 흐름을 통과하며, 출처를 강제 선택하지 않아도 된다.
5. 내부 기획 편집기에서 만든 PRD가 파일 import와 동일한 작업 schema를 사용하고, 개발 결과의 피드백을 어디서든 읽을 수 있는 Markdown으로 내보낸다.
6. 기획안 업데이트 시 기존 승인본과 변경 사항·영향 Task를 보여주며, 승인 전 실행 Task가 변경되지 않는다.
7. 한 제공자에서 테스트가 실패하면 AI 완료 메시지에 관계없이 `Done`으로 표시되지 않는다. 독립 AI 리뷰 없음과 테스트 실패를 구분한다.
8. 승인 거절과 서버 강제 종료 뒤에도 작업/로그는 보존되고 중복 실행되지 않는다.
9. 연결된 제공자의 지원 사용량 지표만 시각화하며, 한도 미확인과 '0% 사용'을 구분한다.
10. 등록하지 않은 경로 접근, 외부 포트 공개, 토큰이 포함된 로그는 차단된다.
11. 사용자가 여러 AI를 연결했다면 읽기 전용 교차 리뷰가 가능하고, 리뷰 결과는 검사 대상 SHA에 연결된다.

## 7. 성과 측정
기획 단계의 추가 측정: **기획 채널과 관계없이** 요구사항 확정 후 개발 인계까지의 수동 조작, 완료 조건 누락 비율, 재기획 변경 추적 가능 여부. 사용자 유형별(단일/다중 AI) 추가 비용과 설정 부담도 측정.
비교 대상: 같은 유형의 기능을 기존 CLI 방식과 관제센터 방식으로 각각 실행한 사례. 측정 항목: 사람이 개입한 횟수, 완료까지의 총 소요, 반복 수정, 실제 테스트 통과, 코드 리뷰에서 확인된 결함, 제공자별 사용량, 세션 재개 시 재설명 부담. 품질을 희생한 속도 개선은 성공으로 보지 않는다.
