# 구현 킥오프 지시서 — Claude Code / Codex 전달용

**현재 상태는 설계까지. 아래 내용은 실제 구현을 시작할 때 복사해 쓸 지시서다.** 저장소가 없는 상태에서는 사용자의 기존 Git 프로젝트를 임의로 수정하거나 인증 정보를 다루지 않는다.

## 권장 사용 방법
- **처음에는 설치된 코딩 에이전트 하나만 환경 스파이크를 담당**하게 한다. 두 번째 AI는 선택적이며 없어도 구현을 진행할 수 있어야 한다.
- 여러 에이전트가 같은 폴더를 동시에 수정하지 않도록 한다.
- 모델은 계정에서 실제 선택 가능한 최신 코딩 모델을 사용한다. 스파이크/구조 설계는 가능하다면 높은 추론 강도, 반복 UI/정형 작업은 기본 강도로 시작해 비교한다. 모델명은 런타임에서 조회한다.

## 최초 지시 프롬프트
```text
이 저장소는 ChatGPT 구독을 요구하지 않는 공급자 중립 AI Coding Control Center 로컬 개발 관제센터 프로젝트다.
먼저 아래 설계 문서를 읽고 핵심 요구사항을 이해해라.
- 00-START-HERE.md
- 01-PRD.md
- 02-TECH-DESIGN.md
- 03-BACKLOG.md
- 04-ADR-RISKS-SOURCES.md
- 06-CHATGPT-PLANNING-BRIDGE.md (ChatGPT 웹 연동은 선택적 시나리오)
- **07-PROVIDER-NEUTRAL-CORE.md (GPT 미사용자 및 단일 AI 경로는 V1 필수)**

최초 작업은 03-BACKLOG.md의 Phase 0에서 **GPT 없는 단일 에이전트 E2E**를 우선 확인하는 데 한정한다. **ChatGPT 웹은 선택 가능한 기획 도구**이며, 내장 기획 편집/외부 기획 import/승인/Task 변환·피드백 export가 어떤 계정 없이도 동작해야 한다.

필수 지침:
1. 먼저 현재 OS/Node/Git와 **설치된** 지원 CLI만 탐지하고, 각 CLI가 제공하는 공식 명령을 조사해라. 미설치 CLI를 필수 오류로 취급하지 마라.
2. 로그인 토큰, auth.json, .env, 자격증명 값을 읽거나 출력·기록하지 마라.
3. 기존 소스 수정, 플러그인 설치, 인증 변경, 새 API 과금 연결은 사용자 승인 없이 하지 마라.
4. 공식 CLI의 문서화된 인터페이스로 연결을 확인하고, 미지원 기능은 미지원으로 보고해라.
5. 프로바이더별 세션/승인/사용량 지원을 실제 관찰된 결과와 추정으로 구분해라.
6. 첫 검증은 임시 Git 저장소와 가짜 데이터에서 수행해라.
7. CloudCLI의 플러그인 API는 기존 Chat 탭 수정 및 에이전트 메시지 전송을 지원하지 않는다는 제약을 반영해라.
8. 각 제공자 CLI의 인증 정책과 구독/API 과금 경계를 준수하라. Codex에 ChatGPT 구독이 없을 수 있으며 API 키 방식은 명시 동의 없는 비용 발생 경로다.
9. Phase 0이 끝나면 검증 표, 실제 실행한 명령, 결과, 실패 원인, 설계 변경 제안, 다음 Phase 작업 분해를 작성해라.
10. 검증하지 않은 기능을 구현 가능하다고 단정하거나, 완료했다고 보고하지 마라.
11. **기획 내부 에디터와 외부 Markdown/JSON/붙여넣기**를 공통 스키마로 구현하고 ChatGPT 계정/대화/메모리 자동 수집 기능을 만들지 마라.
12. 새 기획 버전을 승인 전 기존 실행 Task에 자동 적용하지 말고, source/provenance + diff + feedback roundtrip을 테스트해라.
13. 공개 HTTPS 터널/ChatGPT 커스텀 MCP 연결은 Phase 3 선택 기능이며 초기 Phase에서 인터넷에 서비스를 노출하지 마라.
14. **Claude-only 또는 Codex-only 한 제공자로 기획→실행→테스트→사용자 승인 E2E가 가능**하도록 만들고, 독립 모델 리뷰 부재가 작업 완료를 무조건 막지 않게 해라.
15. Gemini CLI/OpenCode는 독립 어댑터 후보로 취급하고 실제 POC 전 가용성/한도를 만들어내지 마라.

구현 코드는 먼저 요청받은 최소 범위만 작성하되 타입 검사와 자동 테스트를 포함해라.
```

## 교차 리뷰 프롬프트
```text
현재 기준 커밋(base)과 대상 커밋(head)을 고정해 변경을 읽기 전용으로 리뷰해라.
- PRD 완료 조건 충족 여부
- 승인·권한·로컬 인증 처리의 우회 여부
- 실행 상태와 검증 상태의 혼동 여부
- idempotency/중복 실행/복구 오류
- 경로 탐색·worktree 충돌·비밀정보 로그 유출
- 테스트 누락, 버전별 가정, OS 종속성

코드를 수정하지 말고 발견사항에 파일/위치/재현 조건/영향/근거를 적어라.
실제 확인된 결함과 추가 검증이 필요한 의심을 분리하라.
취향 차이 수준의 리팩터링 권고는 결함과 구분하라.
```
