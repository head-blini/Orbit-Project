# Orbit — 확정 개발 범위 v1.0

- 승인 기준일: 2026-10-27, Asia/Seoul
- 기준 ID: `ORBIT-SCOPE-2026-10-27-v1.0`
- 상태: 사용자가 대화에서 승인한 제품 범위의 고정본. 기능 구현 완료를 뜻하지 않는다.
- 저장소에 반영할 위치: `docs/ORBIT-SCOPE.md`
- 개발 담당: **Codex만**. Claude Code·ChatGPT 웹은 Orbit 제품의 연동 대상이다.
- 목적: 개인 실사용이 우선. 충분히 검증한 뒤 사내 공유를 검토한다.

## 1. 제품 정의와 변경 원칙

Orbit은 ChatGPT 웹·Codex·Claude Code를 한 프로젝트에서 사용하면서, 승인된 목표·제약·결정 이유·작업 인계·진행 상황·결과물을 유지하는 로컬 우선 AI 작업 공간이다.

사용자는 이미 Claude Code의 Codex 호출과 브라우저를 통한 ChatGPT 웹 요청·응답 수집을 사용하고 있다. 문제는 단순 연결의 부재가 아니라 방향성 이탈, 반복 설명, 진행 상황의 분산이다. 기존 도구를 다시 써보라는 단계로 되돌아가지 않는다.

핵심 흐름은 다음으로 고정한다.

`요구사항·자료 입력 → 기획 AI/모델 선택 → 작업 명세 검토·승인·저장 → 프로젝트 이동 → 실행 AI/모델 선택 → 실행·인계·검토 → 결과물·검증·후속 작업`

코딩은 여러 작업 유형 중 하나다. 분석·조사·문서·이미지·데이터·자동화 작업을 배제하지 않는다. 모든 요청에 거대한 개발 기획서를 만들거나 Git 저장소를 요구하지 않는다.

### 검토한 선택지와 확정 방향

- 기존 도구와 지침만 사용: 이미 겪는 연속성·가시성 문제를 충분히 해결하지 못하므로 최종안이 아니다.
- **기존 실행기와 Orbit의 공통 기준·인계·작업 화면 결합: 채택.** 현재 구현을 재사용한다.
- 모든 제공자·마켓플레이스·복잡한 다중 에이전트를 포함한 전면 재구축: 이번 우선 범위가 아니다.

최신 사용자 승인 변경은 새 버전과 변경 이유로 남긴다. 이 문서는 충돌하는 이전 초안의 제품 범위와 우선순위를 대체하지만 기존 보안·데이터 보존 규칙을 완화하지 않는다. 시스템·조직 정책을 덮어쓰는 문서도 아니다.

새 AI 기능의 등장은 전체 재설계의 근거가 아니다. 동일 요구사항을 더 잘 구현하는 어댑터 교체는 검증 후 허용하되, 필수 기능 축소·새 기능 확장·과금 방식 전환은 변경 제안으로 분리한다.

## 3. 방향성 유지 계약 — F03/F05

승인된 기준에는 목표, 현재 범위, 제외 범위, 제약, 결정과 이유, 완료 조건을 포함한다. AI의 새 제안은 승인본을 자동 변경하지 않는다.

- 승인 범위 안의 구현·수정·검증은 자율적으로 진행한다.
- 목표/범위/핵심 완료 조건 변경은 사용자 승인 후 새 버전으로 반영한다.
- 권한 확대·외부 전송 목적지 변경·추가 과금·파괴적 작업은 관련 승인을 별도로 적용한다.
- 각 실행은 사용한 기준 버전/해시와 관련 결정을 참조한다.
- 기준 변경 시 과거 증거를 삭제하지 않는다. 영향받는 작업만 재검토·재검증 대상으로 표시한다.
- 실행 중인 작업의 기준을 무음 교체하지 않는다. 계속 진행/중단/재계획 여부를 명시적으로 처리한다.
- 승인과 실행 허용은 서버에서 확인한다. 프롬프트에 ‘지켜라’라고 쓰는 것으로 대체하지 않는다.

Handoff는 전체 대화 무차별 복사 대신 다음 정보를 묶는다.

`projectId / taskId / sourceRunId / 승인 기준 버전·해시 / 목표·제약 / 결정·이유 / 관련 입력·결과물 참조 / 현재 검증 / 미해결 문제 / 다음 작업 / 허용된 도구·전송 범위`

인계 목적지·시각·자료·검증 결과를 남긴다. 모델 내부 사고나 전용 세션 상태까지 이전한다고 표시하지 않는다. 다음 AI가 자료를 받았다는 사실과 실제로 준수했다는 검증도 구분한다.

## 4. 진행 상태 화면 — F06 필수

### 표시 수준

| 수준 | 표시할 정보 |
|---|---|
| 프로젝트 | 승인된 목표·버전, 전체 단계, 작업 수, 완료 조건 충족 수, 현재 차단·승인 요청 |
| 작업 | 담당 AI/모델, 현재 단계, 선행 작업, 시작 시각, 관측된 실행·대기 시간, 결과물, 다음 조치 |
| 실행 상세 | 관측 가능한 도구 호출·명령·파일 변경·검토·인계, 출처와 시각, 비밀정보 제거 기록 |

기본 화면은 요약, 상세는 펼침 방식으로 한다. 모델의 비공개 내부 사고가 아니라 관측 가능한 활동을 표시한다. AI가 스스로 설명한 현재 활동은 모델 보고로 표시하고 직접 관측한 도구 이벤트와 구분한다.

### 상태 의미

`대기 / 실행 준비 / 실행 중 / 승인 대기 / 한도 대기 / 선행 작업 대기 / 검증 중 / 중단 요청 / 중단 확인 / 오류 / 연결 유실·확인 불가 / 재검증 필요 / 완료`

이것을 반드시 하나의 enum으로 압축할 필요는 없다. 실행 상태, 연결 관측 상태, 검증 상태, 승인 상태를 분리하고 화면에서 집계하는 방식을 권장한다.

- ‘AI 응답 종료’, ‘도구 종료’, ‘검증 통과’, ‘사용자 승인’은 서로 다른 사실이다.
- 마지막 이벤트 수신 시각과 마지막 유효 관측을 표시한다. 새 이벤트가 없다고 즉시 실패 또는 완료로 바꾸지 않는다.
- 중단 요청 전송은 중단 성공이 아니다. 종료를 확인하지 못하면 충돌 실행을 격리한다.
- 오류·대기는 원인, 보존된 결과, 사용자가 할 수 있는 다음 조치를 보여준다.
- 연결이 끊기면 오래된 화면임을 명확히 표시한다. 하트비트가 살아 있다는 것만으로 모델이 실제 작업 중이라고 확정하지 않는다.
- GET/새로고침/화면 재접속은 실행이나 재시도를 일으키지 않는다.

### 진행률

기본 표시는 `작업 8개 중 5개 완료`, `완료 조건 12개 중 7개 확인`이다. 숫자는 화면 예시이며 고정 목표가 아니다.

진행 막대는 작업 수 기준인지 완료 조건 기준인지 표시한다. 작업 수를 시간·노력의 비율로 해석하지 않는다. 근거 없는 87%나 남은 시간 예측은 만들지 않는다.

계획 버전별 분모를 보존하고, 변경 시 추가/제외/재검증 내역을 보여준다. 필수 조건을 삭제해 완료율을 높이지 않는다. 재검증 필요 상태와 통과 상태를 혼합하지 않는다.

### 이벤트·영속화 구현 지침

기존 이벤트 저장과 실시간 전달 경로를 먼저 재사용한다. 내부 이벤트에는 프로젝트·작업·실행·부모 실행·기준 버전·출처·관측 시각·수신 시각을 연결한다. 중복 이벤트·늦은 이벤트·순서 역전에 대한 규칙을 둔다. 공급자 이벤트 ID가 없으면 이를 만들어 받았다고 주장하지 않는다.

재연결 시 기존 기록과 최신 snapshot을 재조정한다. 앱/서버 재시작 후 상태가 남아야 하지만 서버가 꺼진 동안 자동 실행됐다고 가정하지 않는다.

## 5. 실행기와 연동 경계 — F04/F07

Orbit이 목표·작업·승인·상태·증거를 관리하고 기존 실행기가 실제 작업 루프를 수행한다. 같은 작업의 실행 소유자는 하나다. Claude가 Codex를 호출하는 경우 하위 실행으로 연결하며 Orbit이 같은 작업을 또 실행하지 않는다.

- Codex: 기존 App Server 경로를 우선 재사용한다.
- Claude Code: 현재 설치/인증 방식과 구조화 실행·이벤트 인터페이스를 확인하고 연결한다.
- ChatGPT 웹: 사용자가 이미 쓰는 브라우저 연계를 먼저 확인한다. 허용된 세션·자료 범위 내에서 대상 대화·선택 모델·전송·답변 완료·요청 대응을 검증한다.
- `codex-plugin-cc`와 유사 네이티브 위임 기능은 출처·버전·권한·이벤트 관측 범위를 확인해 재사용한다. 플러그인 존재만으로 완료 게이트 충족으로 보지 않는다.

ChatGPT 웹을 허락 없이 유료 API로 대체하지 않는다. 수동 가져오기/내보내기는 복구 수단일 뿐 자동 연동의 완료 증거가 아니다. 웹 연결이 막히면 그 요구사항을 차단 상태로 보존하고 다른 독립 작업을 계속한다.

쿠키·토큰 추출, 인증 우회, CAPTCHA 우회, 차단 우회를 하지 않는다. 서비스 지원 조건·권한과 기술적 관측 한계를 확인하고 필요한 변경만 사용자에게 요청한다.

원시 모델 연결과 에이전트 런타임을 구분한다. 지원되지 않는 모델·도구·추론 설정을 사용 가능으로 노출하지 않는다.

## 6. UI 구성 — F01/F02/F11

- 홈: 요구사항 입력, 자료, 기획 AI 선택, 최근 프로젝트.
- 프로젝트: 작업 진행판을 기본으로 하며 기준·결정 / 결과물 / 실행 기록을 연결한다.
- 연결·도구: AI 연결 상태, 계정 별칭, 모델/기능 검증 상태, 프로젝트 도구 프로필.
- 사용량·설정: 출처 있는 한도/초기화/비용과 기본 모드·권한 설정.

간편 모드는 실행에 필요한 최소 선택과 현재 할 일을 보여준다. 고급 모드는 단계별 모델·지원 추론 강도·인계 내용·도구·정책·이벤트·증거를 펼친다. 두 모드의 보안 정책은 동일하다.

코드 작업에서만 diff·worktree·테스트·병합 정보를 확장한다. 기존 메뉴와 기능은 회귀 없이 재배치하고, 새 요구사항을 핑계로 기존 기능을 삭제하지 않는다.

## 7. 결과물·사용량·도구·복구 — F08/F09/F10

결과물은 실제 파일 또는 확인 가능한 외부 참조와 버전·생성 작업·출처·검증 상태를 가진다. 파일 존재/형식/읽기 가능성과 의미적 정확성을 구분한다. 코드에는 테스트·빌드, 분석에는 입력 수치·출처, 문서에는 내용·열기·형식, 이미지에는 파일·규격·요청 일치 검사를 적용한다.

이미지 생성 엔진이나 모든 편집기를 직접 만들지 않는다. 검증된 연결 도구를 사용하고 미연결 기능은 미연결로 표시한다. 미지원 출력 형식을 성공처럼 보여주지 않는다.

사용량은 계정·모델 또는 실제 제공된 quota 구간·출처·갱신 시각과 함께 표시한다. 공유 quota는 같은 풀임을 표시하고 두 서비스 수치처럼 중복 합산하지 않는다. 알 수 없는 값을 0·무제한으로 바꾸지 않는다. 구독 한도와 API 비용은 분리한다.

도구는 프로젝트별로 선택한 검증된 Skills·MCP·Plugins를 사용한다. 설치됨/설정됨/연결됨/정책상 허용됨/실검증됨을 구분한다. 임의 자동 설치·활성화는 후순위다.

실행 전 의도를 기록하고 요청·응답·세션·결과 증거를 연결한다. 중복 요청과 자원 충돌을 막고, 불명확한 실행은 확인 전 자동 재시도하지 않는다. 재개·재시도·모델 인계에도 승인 범위와 누적 한도를 유지한다. 지원되지 않는 네이티브 재개는 명시적 인계로 처리한다.

기존 sandbox·반출 검사·승인·loopback·자원 잠금은 유지한다. 네이티브 CLI 내부의 모든 전송을 Orbit이 통제한다고 주장하지 않는다. 비밀정보는 브리핑·인계·로그·화면에 저장/노출하지 않는다.

## 8. 후순위 — 삭제하지 말고 별도 backlog로 보존

- 모든 제공자(Bedrock/LiteLLM/vLLM 등)의 실연결 확대. 기존 구현과 확장 경계는 보존.
- 복잡한 토론·경쟁·대규모 병렬 협업. 이번에는 단일 실행·순차 인계·교차 검토 중심.
- 확장 마켓플레이스·자동 설치·검증 없는 최신 기능 수집/적용.
- 고급 소스 그래프·전용 시각화 편집기 확장. 기존 구현은 보존.
- 임의 외부 서비스 예약 자동화와 상시 daemon.
- 다중 사용자·조직 권한·사내 배포·공용 계정 운영.

## 10. 개발 재개 규칙

1. 현재 로컬을 먼저 확인한다. 원격 커밋으로 reset하거나 새 clone으로 최근 작업을 대체하지 않는다.
2. 적용되는 지침과 기존 Goal/계획의 충돌을 확인하고 최신 승인 범위를 저장소 문서에 반영한다. 전역 지침·사용자 비밀정보는 무단 수정/열람하지 않는다.
3. 기준선 확인은 한 번 수행해 재사용/차이/미검증을 기록한다. 감사·설계 문서만 계속 만들며 구현을 미루지 않는다.
4. 동일한 로컬 스택·테스트·저장 구조를 우선 재사용한다. 작은 단위로 실패 테스트→구현→회귀/브라우저 검증을 진행한다.
5. 안전한 변경은 이 승인 범위 안에서 계속한다. 로그인·추가 비용·새 권한·데이터 손실 위험·범위 변경만 별도 요청한다.
6. 개발은 Codex 전담. Codex 내부의 지원되는 서브에이전트 활용은 가능하나 공용 DB/타입/Controller 동시 수정을 피한다.
7. 승인 없는 원격 push·배포·운영 변경, reset --hard/clean/강제 덮어쓰기를 하지 않는다.
8. 실제 수행한 검사·실패·skip·blocked·미검증을 구분한다. 기존 테스트 수치나 fixture를 신규 live 성공으로 바꾸지 않는다.
9. 개발 진행도 요구사항 ID별 구현/단위/통합/브라우저/live/차단/다음 작업으로 기록한다. 이는 제품의 실시간 진행판을 대신하지 않는다.
10. 한도/중단 시 변경·검사·남은 작업·다음 실행 지점을 저장한다. ‘나중에 자동 재개’를 보장하지 않는다.
