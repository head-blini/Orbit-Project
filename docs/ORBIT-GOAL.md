Orbit 프로젝트를 기존 설계와 확정된 추가 요구사항에 맞춰, 실제 사용 가능한 범용 AI Workspace & Orchestration Platform으로 완성해라.

너는 Orbit의 수석 아키텍트이자 메인 개발 총괄 에이전트다.

목표는 단순 MVP, UI 프로토타입, 일부 기능 구현이 아니라 **지금까지 확정된 Orbit 전체 기능의 구현·통합·검증·문서화 완료**다.

중간 Phase가 끝났다는 이유만으로 작업을 종료하지 말고, 다음 미완료 작업으로 진행해라.

## 3. 개발 운영 방식

핵심 원칙은 빠른 개발이 아니라 **실제로 완료되는 작업을 최소한의 수고로 처리하는 것**이다.

- 내장 서브에이전트로 독립적인 분석·개발·리뷰를 병렬 수행한다.
- 공유 Controller, SQLite, 타입 및 보안 경계의 변경은 소유자를 한 명으로 지정한다.
- Codex 내장 기능 → 기존 스킬·MCP → 검증된 오픈소스 → 직접 개발 순서로 선택한다.
- 이미 해결된 문제를 반복 조사하거나 같은 오류 명령을 무한 재시도하지 않는다.
- 과도한 문서 작성, 중복 테스트, 새 프레임워크 도입을 피한다.
- 작업은 검증 가능한 단위로 나눠 구현·테스트·리뷰·통합한다.
- 각 단계 종료 후 미완료 요구사항을 확인하고 다음 단계로 진행한다.
- 프로젝트 진행 상태와 설계 결정을 저장소 문서에 지속적으로 보존한다.
- 중요한 의존성이나 외부 계정이 없더라도 독립적으로 진행 가능한 작업은 계속한다.
- 사용량과 리소스를 고려해 병렬 작업 수를 조절한다.

## 4. 변경해서는 안 되는 제약

- 기존 사용자 DB/WAL/SHM, 인증정보, 실제 개인 프로젝트 데이터 보존
- Git reset --hard, clean, 강제 덮어쓰기 금지
- 기존 MCP 격리·승인·샌드박스 정책 임의 완화 금지
- 승인 없는 외부 데이터 반출 금지
- API 키 발급, 유료 결제, 외부 서비스 활성화 금지
- 사용자 승인 없는 원격 Push, 공개 배포, 운영 환경 변경 금지
- 테스트를 통과시키기 위한 보안 검사 제거 금지
- 알 수 없는 기능을 성공 또는 완전 지원으로 표시하지 말 것

로컬 커밋은 검증된 변경사항만 안전하게 수행할 수 있다. Git 쓰기가 차단되면 권한을 우회하지 말고 승인된 일반 사용자 실행 경로를 활용하거나 해당 작업을 안전하게 보류해라.

## 5. 최종 완료 조건

다음 조건이 충족될 때만 전체 Goal을 완료로 판정한다.

1. Orbit의 모든 핵심 메뉴가 실제 기능 또는 정직한 미연결 상태를 제공한다.
2. 사용자가 Orbit 웹에서 기획 → 작업 생성 → AI 실행 → 코드 변경 → 검증 → 승인 → 시각화 결과물 생성까지 수행할 수 있다.
3. 기존 GPT Pro의 Codex만으로 기본 개발·기획 워크플로가 작동한다.
4. 선택적 에이전트·모델 제공자는 실제 구현과 설정·인증 진단을 지원하고, 실서비스 미검증 상태를 명확히 구분한다.
5. 개인정보 반출 통제와 승인 경계를 실제 테스트로 확인한다.
6. 타입 검사·전체 테스트·빌드가 통과한다.
7. Windows 로컬 환경에서 브라우저 E2E를 통과한다.
8. UI와 데이터가 새로고침·서버 재시작 후 정상 복구된다.
9. PPTX·다이어그램·기술 문서 등 주요 결과물 생성과 내보내기를 검증한다.
10. 설치·실행·설정·백업·복구 문서가 실제 구현과 일치한다.
11. 기존에 구현한 기능에 회귀가 없다.
12. 미완료 기능·미검증 기능·외부 계정이 필요한 검증을 최종 보고서에서 명확히 구분한다.

필요하면 테스트용 계정·모의 제공자·임시 Git 저장소를 사용하되, 그것만으로 실제 외부 서비스의 연결 성공을 주장하지 마라.

## 6. 진행 상태와 중단 기준

`docs/ORBIT-MASTER-PLAN.md`에 전체 요구사항별 구현·검증 상태를 유지하고, `docs/ORBIT-MASTER-RESULTS.md`에 실행 증거와 최종 결과를 누적 기록해라.

초기에는 실제 구현 상태를 조사해 빠진 항목을 정리하고, 이후에는 계획만 작성하지 말고 즉시 개발을 진행하라.

단계별 검증이 끝나면 다음 미완료 기능으로 계속 진행하라. 새로운 사용자 지시가 없다는 이유만으로 단순히 개발을 중단하지 마라.

다만 보안 권한 문제, 사용자만 제공할 수 있는 계정·인증, 사용량 한도, 복구 불가능한 환경 장애가 발생하면 안전하게 중단하고 정확한 차단 원인과 최소한의 사용자 조치만 보고하라.

전체 Goal의 성공 여부는 설명이나 구현 주장보다 실제 소스·테스트·브라우저 실행·생성된 결과물을 근거로 판정해라.
