# Codex 개발 재개 지시

권장 설정: 사용자가 사용 중인 **Astra / Extra High**가 실제 선택 가능하면 초기 통합·마이그레이션 검토에 사용한다. 반복적인 작은 구현은 필요에 따라 High로 낮춘다. 제품 내부 모델 선택과 개발 모델 선택은 별개다.

기존 Orbit 로컬 폴더에서 실행한다. 과거 전체 A–K 목표가 실행 중이면 안전한 체크포인트에서 중단/일시정지하고, 이전 목표·진행 기록을 보존한 뒤 새 범위를 적용한다. 새 원격 clone으로 현재 로컬을 대체하지 않는다.

첨부 `ORBIT-SCOPE-2026-10-27.md`와 `ORBIT-IMPLEMENTATION-PLAN-2026-10-27.md`를 Codex에서 읽을 수 있게 추가한 뒤 아래를 전달한다. `/goal` 지원 환경에서는 첫 줄을 포함해 목표로 설정한다. 지원되지 않으면 `/goal`만 제거한 일반 지시로 실행하고 진행 문서는 유지한다.

```text
/goal Orbit을 승인된 ORBIT-SCOPE-2026-10-27-v1.0의 F01~F11 및 A01~A16에 맞춰 실제 사용 가능한 상태까지 구현·통합·검증하라. 이번 지시는 읽기 전용 감사 요청이 아니라 개발 재개 승인이다. 단, 안전 경계와 별도 승인이 필요한 행위는 그대로 유지한다.

[기준과 역할]
첨부 ORBIT-SCOPE-2026-10-27.md 전체를 먼저 읽고 docs/ORBIT-SCOPE.md에 보존하라. 같은 파일이 있으면 비교하고 변경 이력을 남기며 병합하라. 첨부 구현 계획은 docs/superpowers/plans/2026-10-27-orbit-resume.md로 반영하되 실제 로컬 경로와 중복 구현을 먼저 확인하라.
Orbit 자체 개발·수정·테스트는 Codex만 담당한다. Claude Code와 ChatGPT 웹은 제품에서 연결·실검증할 대상이지 Orbit 코드 개발을 위임할 도구가 아니다.
최신 사용자 승인을 받은 범위가 충돌하는 과거 제품 범위·우선순위보다 우선한다. 기존 안전 규칙은 낮추지 마라. 사용자에게 필요성을 다시 묻거나 제품을 코딩 전용으로 축소하지 마라.

[고정 기능]
F01 요구사항 입력·기획 AI/모델 선택·작업 명세 생성.
F02 Git 없는 분석·문서·이미지 등도 가능한 프로젝트와 후속 작업.
F03 목표·범위·제약·결정 이유·완료 조건의 승인본/버전, 변경 제안과 승인 분리.
F04 Codex·Claude Code·ChatGPT 웹 세 도구의 실제 작업 연동.
F05 승인 기준·결정·자료·결과·증거·남은 문제를 자동 인계.
F06 프로젝트/작업/실행 진행판, 현재 단계·담당·활동·마지막 관측·대기 이유·결과·검증.
F07 단일 실행·순차 인계·선택적 교차 검토와 후속 수정.
F08 실제 결과물 보존·조회·미리보기/열기·버전·유형별 검증.
F09 중단·연결 유실·한도 대응·안전한 재개/인계·중복 방지.
F10 단계별 모델/지원 추론 강도, 계정별 한도·초기화·출처, 프로젝트 도구/권한.
F11 동일 데이터와 정책을 쓰는 간편/고급 모드.

[먼저 할 일]
실제 cwd, branch, HEAD, dirty 상태, 적용 지침, 기존 실행 중 작업, 로컬/원격 차이를 읽기 전용으로 확인하라. 과거 원격은 23a9296, 과거 로컬 기록은 faba903이지만 둘 다 현재 상태라고 단정하지 마라.
AGENTS.md와 적용되는 override, ORBIT-GOAL, MASTER-PLAN/RESULTS, 최신 인계와 실제 코드를 비교하라. 현재 OS/도구/Node 요구사항과 package scripts도 확인하라. 비밀정보 파일 원문은 읽거나 출력하지 마라.
변경 전에 재사용/보완/검증차단만 짧게 보고하라. 합의한 범위의 안전한 변경은 다시 승인받느라 멈추지 말고 이어서 수행하라.
AGENTS.md는 공통 기준을 참조하는 간결한 진입점으로 정리하고, 과거 Goal과 계획에는 이번 범위 및 후순위 연결을 명시하라. 기존 안전·증거·사용자 변경 보존 지침은 유지하라.
이전 지침이 세션에 남을 수 있으므로 적용된 지침과 읽은 기준 ID를 확인하라. 다음 세션도 같은 문서를 읽게 하라.

[진행 순서]
현재 로컬을 기준으로 기준선·회귀 상태를 한 번 확인하라.
공통 기준/작업 결속/이벤트·복구 경계를 재사용·보완하고, Codex 실행 하나가 진행판에서 보이는 세로 흐름을 일찍 완성하라.
범용 프로젝트·기획·간편/고급 UI를 연결하고 Claude Code와 ChatGPT 웹 어댑터·인계·검토를 완성하라.
결과물·검증·사용량·도구 프로필·안전한 복구를 통합하고 코드/비코드 종단간 시나리오로 회귀 검증하라.
이 순서는 의존성에 맞춰 조정할 수 있지만 필수 범위를 줄이거나 전체 완료 조건을 바꾸지 마라.
이미 구현·검증된 기능은 다시 만들지 마라. 새 프레임워크·별도 오케스트레이션 엔진·불필요한 문서 체계를 만들지 마라.

[진행 상태 필수 규칙]
AI 응답 종료, 실행 종료, 검증 통과, 사람 승인을 분리하라.
진행률은 작업 수·완료 조건 수와 기준 버전을 표시하라. 근거 없는 백분율/예상 시간은 만들지 마라.
대기 이유는 승인/한도/선행 작업/오류/연결 유실로 구분하고 마지막 관측 시각과 다음 조치를 보여라.
AI 자체 설명과 직접 관측 이벤트를 구분하라. 비공개 사고를 노출하려 하지 마라.
새로고침·재시작·이벤트 중복/역전/누락 후 복구하되 조회 자체로 작업을 시작하거나 재시도하지 마라.
진행 중 승인 기준이 바뀌면 영향과 재검증을 표시하라. 중단 요청을 종료 성공으로 처리하지 마라.

[연동·안전]
기존 Codex App Server·Claude 실행 기능·검증된 플러그인과 사용자의 ChatGPT 웹 브라우저 연계를 먼저 재사용하라.
한 작업에 실행 소유자는 하나다. Claude가 Codex에 위임하면 부모-자식 실행으로 기록하고 중복 실행하지 마라.
웹 연동을 API나 수동 가져오기로 대체하고 자동 연결 완료로 보고하지 마라.
로그인·쿠키·토큰 탈취/복사, 인증·CAPTCHA·권한 우회는 금지한다. 추가 로그인/설치/권한/유료 과금은 필요한 항목만 요청하라.
기존 DB/WAL/SHM·파일·커밋·사용자 변경을 보존하라. 마이그레이션은 일관된 백업/복원과 복사본 테스트를 먼저 하라.
reset --hard, git clean, 강제 덮어쓰기, 승인 없는 push/배포/운영 변경을 하지 마라. 보호 정책·테스트 assertion을 지워 통과시키지 마라.
세 도구 실검증 중 하나가 막히면 해당 항목을 blocked로 유지하고 가능한 독립 작업을 계속하라. 세 연동 미검증 상태에서 전체 완료라 하지 마라.

[검증과 기록]
작은 변경마다 필요한 실패 테스트→구현→통과 확인을 하라. 안전한 격리와 현재 테스트 체계를 재사용하라.
공유 Controller/HTTP/SQLite/타입 변경은 소유자를 하나로 지정하라. Codex 서브에이전트는 지원되는 환경의 독립 작업에만 사용하라.
docs/ORBIT-STATUS.md에 F01~F11별 구현·단위/통합·브라우저·실연동 검증·차단·다음 작업을 실제 증거로 기록하라.
기존 MASTER-PLAN/RESULTS는 중복 상태 원본이 아니라 같은 기록의 참조 또는 기존 이력으로 정리하라. 충돌하는 두 현황표를 만들지 마라.
최종 보고에는 현재 branch/HEAD, 변경 파일, 실행한 명령과 종료 코드, 통과·실패·skip·blocked, 실제 산출물, 사용자 확인이 필요한 항목을 남겨라.
한 단계 종료를 전체 완료로 보고하지 마라. 문서/감사/화면 목업에서 멈추지 말고 안전한 범위의 다음 구현을 계속하라.
한도·중단 시 현재 상태와 정확한 재개 지점을 기록하라. 실행 환경이나 사용자 승인 없이 백그라운드 자동 재개를 약속하지 마라.

지금은 짧은 기준선 보고 후 범위 고정 문서를 저장소에 반영하고, 첫 미완료 단위를 구현·검증하는 것부터 시작하라.
```

주의: Goal은 스레드 목표다. 저장소의 확정 범위·진행 기록을 대신하지 않는다. 모델 한도·환경·권한 문제로 멈출 수 있으며, 이것을 전체 완료로 취급하지 않는다.
